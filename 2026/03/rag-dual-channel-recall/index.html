RAG 双路召回实战：向量检索 + BM25 与 RRF 融合策略
字数总计：822   |   阅读估时：3分钟
  1. 向量检索的盲区
  2. BM25 的互补性
  3. 实现：并行召回 + RRF 融合
  4. 效果与下一步
  5. 小结

企业知识库问答最容易翻车的环节不是生成，而是召回——资料没捞出来，模型再强也只能编。这篇讲我们在企业版知识库落地的双路召回方案：为什么单靠向量不够，BM25 怎么补位，两路结果怎么融合。

向量检索的盲区

向量检索（Embedding + Milvus）语义泛化能力强：”报销流程”能召回”差旅费怎么报”。但它的死穴也很明显：

  • 专有名词、编号、精确 token：查询”错误码 E10023”，向量空间里 E10023 和 E10024 挨得极近，容易召回隔壁错误码的文档——而用户要的是精确匹配；
  • 新词/内部黑话：没在 Embedding 训练分布里的新业务名词，向量表示失真；
  • 关键词完全不重叠的场景反而没问题，那是它的主场。

BM25 的互补性

BM25 是经典的词频统计检索（ElasticSearch 默认打分算法）：term 命中越多、文档越短，得分越高。它和向量恰好互补：

场景 向量 BM25
语义改写（”咋报销”→”报销流程”） ✅ 强 ❌ 弱
错误码/编号精确匹配 ❌ 弱 ✅ 强
内部产品黑话 一般 ✅ 强
长文档语义段落 ✅ 强 一般

所以方案很自然：两路并行召回，谁也别替代谁。

实现：并行召回 + RRF 融合

RRF（Reciprocal Rank Fusion）的妙处在于不需要归一化分数：向量的余弦相似度和 BM25 的得分量纲完全不同，没法直接加权求和；RRF 只看名次，每路第 r 名贡献 1/(k+r)，两路都召回的文档自然分数叠加。k=60 是社区经验默认值，我们没调过它也够用——RRF 对参数不敏感，这是它优于加权融合的另一点。

几个实践细节：

  • 两路 top_k 各取 20，融合后保留 10~15 个进重排，宁滥勿缺——重排阶段还能筛；
  • 向量路对超短查询（<4 个字）效果差，可以先做查询改写（LLM 扩写或同义词表）再嵌入；
  • BM25 路对中文要配好分词器（IK 分词 + 自定义企业词典），产品名、黑话进词典收益立竿见影。

效果与下一步

双路召回上线后，内部 200 题标注集的端到端召回准确率比纯向量提升了约 10 个点。但召回进来的 20 个候选里还有噪声——下一步靠重排（Rerank）模型精筛，以及上下文压缩控制注入 Prompt 的长度，这是下一篇的主题。

小结

RAG 召回的正确心态：不要寻找银弹，要找互补的组合。向量管语义、BM25 管精确、RRF 管融合、Rerank 管精筛——每一环都只解决一部分问题，拼起来才是 90%+ 的准确率。
