MyBatis-Plus 使用踩坑合集：逻辑删除、分页与多表联查

MyBatis-Plus（简称 MP）是 Java 后端的效率神器，单表 CRUD 几乎不用写 XML。但”少写代码”的另一面是”魔法太多”，线上踩过的坑一个比一个隐蔽。记录几个印象最深的。

坑一：逻辑删除后，唯一索引冲突

配置了逻辑删除（@TableLogic）之后，删除其实是 UPDATE deleted = 1。问题来了：如果 username 上有唯一索引，删掉用户 A 再注册同名用户 A，唯一索引直接冲突——因为物理上那行记录还在。

解决方案二选一：

  • 唯一索引改成联合唯一：(username, deleted)，逻辑删除字段参与索引；
  • 或者注册前先物理清理历史删除数据（定时任务冷备后真删）。

小结

MP 用得越熟越要敬畏它的”自动”：自动填充、自动逻辑删除、自动 join 猜测，每一层魔法都可能在某个边界条件下反噬。核心建议就一条——读懂它生成的 SQL，比记住 API 重要得多，mybatis-plus 打开 SQL 日志调试应该成为肌肉记忆。
