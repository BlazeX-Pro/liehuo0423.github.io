JVM 学习笔记：内存区域、垃圾回收与面试常考题

毕业季求职，JVM 是绕不过去的关卡。这篇文章把我刷题+看源码后整理的 JVM 核心知识过一遍，按”内存区域 → 对象创建 → 垃圾回收 → 参数调优”的顺序展开。

运行时数据区

JVM 内存主要分这几块：

区域 线程私有? 存什么 OOM 风险
程序计数器 是 当前字节码行号 唯一不会 OOM 的区域
虚拟机栈 是 栈帧（局部变量表、操作数栈） StackOverflowError
堆 否 对象实例、数组 OutOfMemoryError: Java heap space
元空间 否 类元数据（JDK8 后在本地内存） OutOfMemoryError: Metaspace

面试高频题：”对象都分配在堆上吗？”——栈上分配和TLAB是两个重要的例外/优化。JVM 会做逃逸分析，确认对象不会逃出方法时可以在栈上分配随方法销毁；即便在堆上，每个线程也会先在 Eden 区私有的一小块 TLAB 里分配，避免多线程指针碰撞的竞争。

对象生死判定

两种主流算法：

  • 引用计数：简单但解决不了循环引用（A 引 B、B 引 A，计数永不为 0）；
  • 可达性分析（HotSpot 采用）：从 GC Roots（虚拟机栈引用、静态属性、常量等）出发，不可达的对象即为可死。

判定死后也不是立即回收，对象有三次”复活机会”——finalize() 方法没有执行过且有必要执行时会被放进 F-System 队列。但这个方法官方都不推荐用（执行时机不确定、无担保），知道概念应付面试即可，业务代码别写。

分代回收的逻辑

堆分新生代（Eden + S0 + S1）和老年代，逻辑是大多数对象朝生夕灭：

  1. 新对象进 Eden，Eden 满了触发 Minor GC（复制算法，存活对象进 Survivor）；
  2. Survivor 里的对象每熬过一次 GC 年龄 +1，默认 15 岁晋升老年代；
  3. 老年代满触发 Major GC / Full GC，成本远高于 Minor GC。

所以调优的一个核心目标就是：让朝生夕灭的对象死在新生代，别晋升到老年代。-XX:MaxTenuringThreshold 调晋升年龄、-Xmn 调新生代大小，都是围绕这一点。

常用参数与排查思路

线上排查 OOM 的标准动作：先拿到堆转储 → MAT 或 VisualVM 打开 → 看 Dominator Tree 找占用大头 → 结合代码定位泄漏点。见过最多的就是静态集合只 add 不 remove、监听器/线程池没释放、以及缓存无上限。

小结

JVM 知识的正确用法不是背八股，而是出问题时有排查抓手：看到频繁 Full GC 想到分代假设被打破（大对象、内存泄漏），看到线程 dump 卡住想到锁竞争。八股是地图，实践才是路。
