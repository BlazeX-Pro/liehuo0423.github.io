大模型应用的”打字机效果”几乎人见人爱，背后是 SSE（Server-Sent Events）在工作。这篇从协议讲到实现，顺便说清楚它和 WebSocket 的边界。

SSE 是什么

HTTP 的传统模式是一问一答：请求发出，等完整响应。SSE 允许服务器单向地、持续地向客户端推送文本事件，基于 HTTP 长连接实现：

格式就三条规则：data: 开头、空行分隔事件、data: [DONE] 约定结束。文本协议、纯 HTTP、自动重连（浏览器 EventSource 断线默认 3 秒重连），比 WebSocket 轻得多。

和 WebSocket 的选择标准：需要双向实时（聊天室、协同编辑）用 WebSocket；只需要服务器持续下推（AI 生成、行情推送、进度通知）用 SSE——AI 对话场景天然是”用户说一句、模型吐一串”，SSE 刚好够用还省掉了连接升级的复杂度。

三个工程细节：

  1. 超时要设：SseEmitter 默认不超时，连接泄漏会拖垮线程池；
  2. 网关要放行长连接：Nginx 默认 proxy_read_timeout 60s，且要关掉响应缓冲（proxy_buffering off），否则网关把 token 攒批发给前端，打字机变成”整段蹦”；
  3. 异常要推给前端：模型中途限流/超时，走 completeWithError 或发一个 error 事件，别默默断开——前端拿不到任何信息是最差的体验。

小结

SSE 是 AI 应用的默认传输方案：比轮询省资源、比 WebSocket 简单、天然适配”逐 token 生成”的模型特性。协议本身半天能学会，值钱的是超时、缓冲、异常这些工程细节——它们决定了 demo 和产品之间的差距。
