Spring AI 快速上手：调通第一个大模型应用
字数总计：692   |   阅读估时：2分钟

对 Java 后端来说，Spring AI 是切入大模型应用开发最平滑的路径——注解和自动配置的味道和 Spring Boot 一模一样。这篇记录从零调通第一个 AI 应用的过程。

引入依赖

Spring AI 目前按模型厂商拆分 starter，以国内常用的通义千问为例：

API Key 一律走环境变量，不进代码库——这是底线。

最小对话服务

ChatClient 是 Spring AI 的核心抽象，屏蔽了不同厂商 API 的差异——换模型厂商基本只改依赖和配置，业务代码不动。这个抽象层的设计和当年 JDBC → JPA 的演进很像。

流式输出

同步接口体验太差（等 10 秒一次性吐一大段），大模型应用必须上流式：

WebFlux 的 Flux 直接对接 SSE，前端用 EventSource 接收，打字机效果就有了。这块的底层原理我后面单独写一篇展开。

Prompt 也要工程化

第一个 demo 跑通后，很快发现真正的功夫在 Prompt 管理上。Spring AI 提供了 PromptTemplate 和外部化模板：

把 Prompt 模板放进 resources 目录、参数化变量、支持多版本切换——团队协作时这是刚需，单人 demo 阶段感受不到。

踩坑记录

  • 超时：模型调用动辄 30 秒+，RestClient 的默认超时要显式调大，否则流式还没开始就断了；
  • 重试：限流错误（429）要退避重试，但内容生成类请求重试要小心重复计费；
  • 日志：调试期把完整 Prompt 打进日志，上线前必须脱敏——日志里泄漏用户数据是大忌（这个话题 2026 年那篇脱敏文章会展开）。

小结

Spring AI 把大模型调用收敛成了 ChatClient 一行代码，但一个生产级 AI 应用的距离恰恰在这一行代码之外：流式、超时、重试、Prompt 版本、评测。框架是入门的快车道，工程化才是这行的护城河。
